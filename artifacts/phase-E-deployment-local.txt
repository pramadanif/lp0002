## A correction worth recording
  getProgramIds returns only LEZ's BUILT-IN programs (amm, authenticated_transfer, pinata,
  privacy_preserving_circuit, token). It is a name registry, not a list of deployed user
  programs, so a deployed program does NOT appear there. This does not affect the version
  fingerprint in docs/VERSIONS.md, which compared exactly those built-in programs.

## U-6 RESOLVED: the SPEL CLI does support the privacy-preserving path

Read from `spel-cli/src/tx.rs` at SPEL main 5126b7ed:

  line 434  `has_private` — true when any account id carries a `Private/` prefix
  line 442  builds `ProgramWithDependencies` (program + deps from `--bin-<NAME>`)
  line 473  `AccountIdentity::PrivateOwned(account_id)` for private accounts
  line 502  `send_privacy_preserving_tx(pp_accounts, instruction_data, &program_with_deps)`
  line 687  public transactions take a different branch: `LeeTransaction::Public(tx)`

So the invocation shape for an anonymous approval is:

  spel --idl artifacts/multisig-idl.json -p artifacts/multisig.bin \
       --bin-membership artifacts/membership.bin \
       -- approve --approver Private/<account-id> ...

The `--bin-<NAME>` dependency mechanism is exactly what resolves the multisig program's
ChainedCall to the membership program, which is the composition ADR-001 D2 describes.

The CLI also generated all four of our instructions from the IDL with correct argument types,
which is independent confirmation that the IDL (criterion P-U3) is well-formed and usable.
